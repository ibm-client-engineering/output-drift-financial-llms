# DFAH-Bench Benchmark Card

## What DFAH-Bench Measures

DFAH-Bench evaluates **behavioral consistency** of LLM agents in financial decision-making. It measures whether agents produce stable decision processes — not just stable outcomes — across repeated identical queries.

Core metrics:
- **DAR/TAR gap**: Do runs agree on the final decision while following different exact tool-call sequences?
- **DCB (Decision Concentration Bias)**: Does the model collapse to a narrow decision subset?
- **ECD (Evidence Contact Divergence)**: Do runs consult different evidence subsets?
- **SCDR (Same Conclusion Different Reasoning)**: Optional embedding-based divergence metric for trajectory text or rationale text when those traces are available

## Intended Use

- Evaluating LLM agent reliability for regulated financial applications
- Comparing behavioral consistency across models, providers, and configurations
- Auditing whether conventional evaluation metrics miss observable trajectory or evidence instability
- Supporting model risk management documentation (SR 11-7, EU AI Act)

## Out-of-Scope Use

- General-purpose LLM benchmarking (use HELM, FinBen, etc.)
- Evaluating model capability or accuracy in isolation
- Real-time production monitoring (this is an offline evaluation benchmark)
- Non-financial domains (metrics are defined over financial task ontologies)

## Replay Protocol

1. Present identical input to agent N times (default N=8)
2. Record: final decision, tool-call sequence, tool outputs, timing
3. Compute per-case metrics across the N runs
4. Aggregate by case, task, and model

## Decision Ontology

| Task | Categories (K) | Labels |
|------|---------------|--------|
| Compliance Triage | 3 | escalate, dismiss, investigate |
| Portfolio Constraint | 3 | approve, reject, modify |
| DataOps Exception | 3 | auto_fix, escalate, quarantine |

## Divergence Channels

The benchmark supports multiple observable channels. Not all channels are available for all models — the channel-availability table (generated by `scripts/audit_channel_coverage.py`) documents this transparently.

| Channel | Availability | Notes |
|---------|-------------|-------|
| Decisions | All models | Always recorded |
| Trajectories | Models that use tools | Empty for pattern-matchers (e.g., Granite, Mistral) |
| Evidence contacts | Models with tool output capture | Partial — depends on logging config |
| Reasoning text | Not available in current data | Requires reasoning capture in future runs |

## Known Limitations

- **English-only**: All prompts and evaluations are in English
- **US/EU regulatory context**: Regulatory references (SR 11-7, EU AI Act) are US/EU-centric
- **Raw corpus vs. paper subset**: Current raw audit reports 8,129 episodes across 30 configs, but finalized paper subsets may be smaller and should be reported explicitly
- **No reasoning text**: The current checked-in raw corpus has 0% reasoning capture
- **Financial domain only**: Task ontologies are financial; generalizability is not claimed
- **Pattern-matchers have empty trajectories**: Models that don't use tools (Granite, Mistral) produce empty tool sequences, limiting trajectory-based analysis
